# PRD Review 检查清单

配合 [`review-workflow.md`](review-workflow.md) 使用。**Must Fix** 导致 FAIL；**Suggest** / **Nit** 不单独导致 FAIL。

## 0. 材料

- [ ] PRD 链接或全文（Leader 派活）
- [ ] Issue / Story Key / 业务背景
- [ ] 可选：原型、数据口径、依赖系统
- [ ] 已读**全文**（非仅摘要）
- [ ] 缺 PRD 或不可访问 → **BLOCKED**

## 1. 价值判断

- [ ] 问题真实、紧迫（非「为做而做」）
- [ ] 预期收益 / KPI-/G- 可衡量
- [ ] 范围与投入匹配；过大应建议分期（Suggest 或 Must Fix 视严重度）
- [ ] 是否考虑过更低成本替代（配置、运营、复用）
- [ ] 无 KPI/成功标准 → 通常 **Must Fix**

## 2. 逻辑闭环

- [ ] 目标 → 方案 → 验收（AC-）链路完整、一致
- [ ] 用户角色与权限覆盖全场景；无越权/缺权限路径
- [ ] 主流程 + 异常流程 + 边界条件
- [ ] 空态、错误态、无权限态有定义
- [ ] **BR-** 无矛盾；状态机闭合
- [ ] 字段/指标口径：分子分母、数据源、刷新频率（涉及时）
- [ ] 依赖与假设显式列出
- [ ] **范围与非范围**清晰；无隐含 scope creep
- [ ] 跨系统 / API / 回写：责任方与边界清楚

## 3. 清晰度（Q- 编号）

- [ ] 无模糊词：适当、优化、等相关、等等、视情况、体验好
- [ ] 每条 FR- 关键能力有对应可测 **AC-**
- [ ] 字段、状态、权限规则有定义（非「待定」散落正文）
- [ ] 原型/图与文字冲突时，PRD 写明以谁为准
- [ ] **OP-** 集中维护；阻塞开发项已标注；有 Owner 或明确待谁确认
- [ ] 问题编号 Q-001…（类型：价值/逻辑/清晰度）

## 4. 编号与结构（Squad 规范）

- [ ] G- / FR- / BR- / AC- / KPI- / OP- / RISK- 使用一致
- [ ] AC- 可客观验证（无纯主观表述）
- [ ] 待确认不混入已确认 FR-/AC-

## 5. 知识库（可选）

- [ ] 若查 KB：仅核对术语/入口/权限别名是否写入 PRD
- [ ] **未**把 KB 历史规则写成当前 PRD 缺陷
- [ ] KB 不可用已标注，未阻断审查

## 6. 输出前自检

- [ ] 已区分 Must Fix / Suggest / Nit
- [ ] 每条 Must Fix 含 PRD 位置（章节或编号）
- [ ] 价值/逻辑摘要已写
- [ ] PASS 时仍写已查重点与残余 OP-/风险
- [ ] 结论只汇报 Leader（未 @ PM / 未推进开发）
