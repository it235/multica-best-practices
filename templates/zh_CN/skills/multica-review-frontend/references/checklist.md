# 前端 Review 检查清单

与 [`review-workflow.md`](review-workflow.md) 配合使用。默认只读审查；**Must Fix** 导致 FAIL，**Suggest** / **Nit** 不单独导致 FAIL。

## 0. 材料与范围

- [ ] 已读 Issue、最新评论、实现者完成说明
- [ ] 已读 impl-spec、UI、API 契约（Leader 派活链接）
- [ ] diff 与变更文件列表一致，且覆盖 issue 目标
- [ ] 审查基于**项目仓库**代码，而非 Multica task 临时目录

## 1. 需求与用户流程

- [ ] 实现满足 issue 用户目标与每条 AC-
- [ ] UI 与接口/状态形成**完整用户流程**（非孤立页面）
- [ ] 无擅自扩大产品范围或业务口径

## 2. 交互与 UI 状态

- [ ] **loading** — 异步请求有加载反馈
- [ ] **empty** — 空数据有说明或引导
- [ ] **error** — 错误可理解，必要时可重试
- [ ] **disabled / permission** — 无权限或不可用态正确
- [ ] **responsive** — 无明显错位（若 PRD/设计有要求）
- [ ] 表单：校验、提交中、**防重复提交**合理

## 3. 列表与数据

- [ ] 列表 **key** 稳定唯一
- [ ] 分页、筛选、刷新逻辑正确且不丢状态
- [ ] 与 API 契约字段、枚举、分页参数一致

## 4. TypeScript 与组件边界

- [ ] 类型清晰，避免滥用 `any`
- [ ] Props / Emits / Expose / Slots 类型明确
- [ ] **不在组件内直接发起 HTTP**（应走项目 api client / hooks）
- [ ] 副作用（订阅、定时器、监听）有清理，无泄漏风险

## 5. 项目模式一致性

- [ ] 复用项目已有组件、hooks、store、api client、类型、样式、工具
- [ ] 未引入**无关重构**或扩大改动范围
- [ ] 符合项目目录与命名约定（若有文档）

## 6. 影响面

- [ ] 共享组件改动是否影响其他页面/团队
- [ ] 路由、导航、权限、缓存是否被意外改变
- [ ] 核心流程（登录、下单、审批等）是否回归风险

## 7. API 契约

- [ ] 请求参数、响应结构、错误码处理对齐契约
- [ ] 错误 UX（toast / 内联 / 重试）合理
- [ ] 与 impl-spec 描述一致

## 8. 测试与验证

- [ ] 关键交互路径有单测或可追溯的手动验证说明
- [ ] 无「无效测试」（永远绿、只测 mock 无断言意义）
- [ ] 实现者验证说明足够可信；不足则写入**剩余风险**

## 9. 可访问性与性能（Suggest 为主，严重时可 Must Fix）

- [ ] 无明显 a11y 阻断（焦点、标签、仅颜色区分状态等）
- [ ] 无明显性能问题（超大列表无虚拟化、重复请求等）— 视 issue 要求

## 10. 输出前自检

- [ ] 已区分 Must Fix / Suggest / Nit
- [ ] 每条 Must Fix 含位置与改法
- [ ] 已说明已跑检查/测试或无法跑的原因
- [ ] 已列出无法验证项
- [ ] PASS 时仍写了已查重点与残余风险
