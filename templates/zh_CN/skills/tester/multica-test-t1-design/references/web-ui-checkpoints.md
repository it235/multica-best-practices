# Web UI Design-to-Case Mapping（UI设计图转测试点）

## ⚠️ UI 检查范围原则（重要）

**Figma 对照检查只覆盖肉眼可辨的页面元素样式，不检查像素级精确值。** 测试用例关注功能的正确性和明显的 UI 状态缺陷，像素级细节（精确尺寸、色值、圆角大小、间距微调等）留给 UI 走查阶段由设计师验收。

- **检查**：元素存在性、布局结构、文案内容、交互状态（默认/悬停/禁用/空态/错误态）、整体视觉风格
- **跳过**：精确位置/尺寸（px值）、精确色值、圆角/边框粗细/阴影量、响应式断点精确像素、字号行高精确值、跨浏览器渲染差异

---

## 从 Figma 设计图提取测试点

当用户提供Figma设计图（截图或描述）时，按以下维度提取测试点：

### 1. 页面元素清单

对设计图中的每个页面元素，建立如下清单：

```
□ 输入框（Input）
  - placeholder文字
  - 前缀/后缀图标
  - 边框样式（常态/聚焦/错误）
  - 输入格式提示
  - 清空按钮

□ 按钮（Button）
  - 文案
  - 颜色风格（常态/悬停/点击/禁用 — 定性描述，不定量）
  - Loading态指示器

□ 下拉选择器（Select/Dropdown）
  - 选项列表
  - 多选/单选
  - 搜索/过滤功能
  - 空选项展示

□ 表格/列表（Table/List）
  - 列定义和顺序
  - 排序功能
  - 分页器配置
  - 行操作按钮
  - 空数据态
  - 选中态样式

□ 弹窗/对话框（Modal/Dialog）
  - 触发方式
  - 遮罩层样式
  - 关闭方式（点击遮罩/关闭按钮/ESC）
  - 标题和内容
  - 按钮布局

□ 导航/菜单（Navigation/Menu）
  - 菜单层级
  - 激活态样式
  - 面包屑导航
  - Tab切换
```

### 2. 交互状态测试维度

对每个可交互元素，检查以下状态（定性描述即可）：

| 状态 | 检查点 |
|------|--------|
| 默认态 | 元素正常显示，无交互时的状态 |
| Hover态 | 鼠标悬停时有视觉反馈（变色/下划线/阴影） |
| Focus态 | 键盘/Tab聚焦时有轮廓样式 |
| Active态 | 点击瞬间有视觉反馈 |
| Disabled态 | 不可操作时置灰并提示原因 |
| Loading态 | 等待中有动画或进度指示 |
| Error态 | 校验失败时红色边框和错误提示可见 |
| Empty态 | 无数据时占位内容合理 |
| Selected态 | 选中项有高亮样式 |

### 3. 常见 Web 页面检查清单

> **注意**：以下检查项中，定量验证（如"1920分辨率"）仅为指示性参考，测试执行时以肉眼判断为准，无需精确测量。

#### 表单页面
- [ ] 所有标签（label）关联正确的输入字段
- [ ] 必填项有标识（* 或 必填文字）
- [ ] 错误提示出现在正确位置（通常在字段下方）
- [ ] 提交按钮在表单未填完时禁用
- [ ] Tab键按正确顺序聚焦字段
- [ ] 回车键触发提交
- [ ] 输入框有合适的输入类型

#### 列表/表格页面
- [ ] 分页组件显示正确的总页数和当前页
- [ ] 每页条数切换后重新加载数据
- [ ] 排序指示器（升序/降序图标）正确
- [ ] 多选时全选/反选功能正常
- [ ] 批量操作按钮在未选择时禁用
- [ ] 列宽调整不影响布局

#### 搜索/筛选页面
- [ ] 搜索框有关键词输入提示
- [ ] 筛选条件支持组合查询
- [ ] 筛选后结果数正确
- [ ] 空搜索结果有提示和建议
- [ ] 清除筛选恢复全部数据

#### 详情/展示页面
- [ ] 所有信息字段完整展示
- [ ] 长文本有展开/收起功能
- [ ] 图片/文件预览功能正常
- [ ] 相关推荐/导航链接正确
- [ ] 加载顺序（骨架屏/loading动画）

#### 响应式/跨浏览器
- [ ] 桌面端布局完整无错乱
- [ ] 小屏幕布局无错乱
- [ ] 关键交互在主流浏览器正常

### 4. 预期结果表述规范

- 使用**定性描述**而非定量描述
- 正确示例：「保存按钮文案正确、颜色醒目、悬停有反馈」
- 正确示例：「错误提示在输入框下方以红色文字展示」
- 错误示例：「按钮尺寸 120x40px、圆角 4px、颜色 #1890FF」
- 错误示例：「输入框宽度 320px、高度 36px」
