## 可执行 + 可追溯（强制提醒）

- 前置条件写「登录具备 {该系统具体权限} 的账号」：**禁止写死个人账号/密码**；也**禁止留下字面 XXX**——权限名由 Agent 按当前系统自行识别填写
- 步骤写真实菜单路径与造数别名；预期对回 AC/PRD
- 详见 `multica-test-t1-design/SKILL.md` 字段要点与 [`design-trace.md`](design-trace.md)

### 功能测试用例示例（权限登录 + 可执行路径）

```
=== 功能测试用例 ===

用例编号: TC-F-CROSSBITE-001
所属模块: 模块B/状态标签/订单查询与打标
测试标题: 标签ACount>0且反覆盖量>1mm时成功打标且可检索
前置条件:
  1. 登录具备 模块B【订单查询】权限的账号
  2. 造数：订单A_ant_ok，订单数 Count=2 且 字段X=1.5
  3. 标签计算已完成
测试数据: Count_前牙=2, 字段X=1.5（AC场景A）
用例类型: 功能流程
优先级: P1
追溯: PROJ-123 AC-A

测试步骤:
  1. 进入 系统A → 模块B → 订单查询，等待加载完成
  2. 选择【标签A】标签（若页面为【标签A】则按实际文案），等待订单广场刷新
  3. 按订单号检索 A_ant_ok，核对标签

预期结果:
  1. 进入订单查询页
  2. 标签选中且列表刷新成功
  3. 结果中出现该订单并显示【标签A】标签
---
```

### 接口测试用例示例

```
=== 接口测试用例 ===

用例编号: TC-I-USER-001
接口名称: POST /api/v1/user/login
测试标题: 验证使用正确的账号密码登录返回成功
请求方式: POST
前置条件:
  1. 测试账号已注册且状态正常（账号取自测试数据配置，不写死个人账号）
  2. 服务正常运行

请求参数:
  {
    "email": "<test_account_email>",
    "password": "<from_secure_test_config>"
  }

预期状态码: 200
预期业务码: 0（表示业务成功）

预期响应体:
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "<string, JWT令牌>",
    "userInfo": {
      "userId": "<number>",
      "nickname": "<string>",
      "avatar": "<string, URL>",
      "email": "<string>"
    }
  }
}
```

校验点:
  - code = 0，表示业务成功
  - message = "success"
  - data.token 为字符串类型，非空
  - data.userInfo.userId 为数字类型
  - data.userInfo.email 与请求参数一致
  - 返回的字段与接口文档一致，无缺失无多余
---
```
