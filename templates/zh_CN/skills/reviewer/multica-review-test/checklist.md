# Test Case Review — 详细 Checklist

配合 `SKILL.md` 使用；按需勾选，不必每项长文解释。

## 0. 材料源（有其一即可）

- [ ] 功能用例 JSON（`jira_key` + `functional`），或
- [ ] XMind：`test_cases_{JIRA_KEY}.xmind`（含 Issue 附件），或
- [ ] 已导入 JIRA/测试管理平台 用例集（步骤 + 预期）
- [ ] 需求依据：Jira Key/链接或已采集 AC
- [ ] 用例源与需求依据**都缺** → 结论 Block

## 1. 交付物与闸门

- [ ] 存在功能用例 JSON（含 `jira_key`、`functional`）
- [ ] 存在 `test_cases_{JIRA_KEY}.xmind`，Key 与 JSON 一致
- [ ] 覆盖报告或等价说明存在（可弱约束；缺失标 Minor，除非用户要求强制）
- [ ] 产物声明为待审；未在 review 流程中导入 Jira
- [ ] 接口用例若有：仅本地；未进入 XMind 功能树

## 2. JSON 结构

- [ ] 每条：`case_id`、`module`、`title`、`preconditions`、`steps`、`expected_results`、`priority`、`coverage_dimension`
- [ ] `len(steps) == len(expected_results)` 且两侧均非空
- [ ] 预期多验证点时用 `1）` `2）` 组织，仍属同一 `expected_results` 元素
- [ ] `module` 为 `/` 路径（如 `概览看板/新订单阶段/阶段切换`）
- [ ] 层级语义：系统前缀 ↔ 需求名 ↔ 业务域/模块 合理，无乱挂

## 3. 禁止项（文本）

- [ ] 无 Confluence wiki 残留：`{LQ}` `{RQ}` `{color}` `{noformat}` 等
- [ ] 无 `[待补充]` `[TBD]` `[占位]` `[缺少Figma…]` 等
- [ ] 无字面权限占位 `XXX` / `某某权限` 未解析
- [ ] 无写死个人账号、密码、私人手机号（需求本身验收白名单除外且仍无密码）

## 4. 优先级

- [ ] 无 `P0`
- [ ] 异常/边界 → P3
- [ ] 核心主验收路径 → P1
- [ ] 其余正常/页面检查等 → P2
- [ ] 无「核心标 P3」或「纯边界标 P1」

## 5. 需求对齐（以当前 Jira 为准）

- [ ] 每条 AC / 关键规则表行有对应用例或有合理解释的 uncovered
- [ ] 无把 138/Confluence 历史**规则**写入 expected 当验收
- [ ] 知识库中的**入口/权限/文案别名**在相关用例步骤中有体现（当前需求范围内）
- [ ] 无当前需求未写的字段/分支/状态被写成测试点
- [ ] 冲突时以当前 AC 为准，报告中可记录差异

## 6. 可执行性

- [ ] 前置：权限语义按**当前系统**填写（非空套话）
- [ ] 步骤含真实菜单/入口或明确后台触发方式（禁止臆造菜单）
- [ ] 需加载处写明等待；造数有别名与关键字段值
- [ ] 预期具体、可判定；无「应该」「可能」「适当」
- [ ] Action+Verify 合并合理；未机械拆成空预期步骤

## 7. 覆盖维度（按需求规模，不强制三维齐全）

- [ ] 有业务路径 → 全量场景覆盖主路径与需求内分支/异常
- [ ] 有输入/限制 → 必要边界（小需求可精简，但关键数值边界不可丢）
- [ ] 有新页/新弹窗 → 页面检查用定性预期（不审 px/色值）
- [ ] 覆盖报告与真实用例一致；无假覆盖

## 8. 抽样策略（与 SKILL 一致）

| 规模 | 策略 |
| --- | --- |
| ≤10 条 | **全审**（P1/P2/P3 均逐条） |
| 11–30 条 | **P1 全审** + P2/P3 **至少 50%** |
| >30 条 | **P1 全审** + **每 module 抽 P2≥1 且 P3≥1** + 查重 |

P2/P3 抽样须覆盖不同 module 与不同 coverage_dimension；发现 Major 可扩大抽样范围。

## 9. 修订后再审

用户授权修订后：

- [ ] 只改问题项，不顺手大扩范围
- [ ] 重生 `test_cases_{KEY}.xmind`（不删其他需求 XMind）
- [ ] 再跑 review；仍不导入

## 10. 结论与导入边界

- [ ] 结论唯一：**Block** | **Revise** | **Pass**（与 SKILL 输出模板一致）
- [ ] **Pass ≠ 导入授权** — 文末仅提示人工确认后对 Tester 下达「审核通过，导入 JIRA」
- [ ] Block/Revise：导入建议写「禁止导入；先修订并重生 XMind」
- [ ] 即使用户对本 Agent 说「导入 JIRA」→ 仍禁止执行 import；请 Tester 处理
- [ ] 审核 测试管理平台 已导入用例集时：核对步骤/预期与当前 AC；不要求必须有本地 JSON 文件路径
