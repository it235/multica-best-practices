# 后端实现专业评审（BackendReviewer）

本 skill 提供对 **后端实现产物（API 契约 + 实现）**的结构化专业评审框架。调用方为 `BackendReviewer`，评审对象为 `BackendDev` 经 `multica-artifact-api-sync` 回传的链接与变更文件列表，以及 Leader 派活时给的架构设计引用。

## 什么时候用

- BackendReviewer 收到 Leader 派发的「评审 API 契约 / 后端实现」任务时。
- 产物修改后进入复审轮次时（对照上一轮修改清单逐条核对）。

## 评审维度（逐项给结论）

1. **契约质量**：字段命名、状态码、错误模型、版本策略是否清晰自洽。
2. **设计吻合度**：实现是否对齐 Architect 方案，偏离须有说明。
3. **错误处理**：异常分支、超时、幂等、边界条件是否覆盖。
4. **单测充分性**：关键路径、边界、异常分支是否覆盖；有无无效测试（标记并阻断）。
5. **TDD 与测试映射**：契约中的 API-ID 是否有对应单元测试；关键路径与异常是否覆盖。
6. **验收对照**：实现是否真正满足每条 AC-。

## 输出格式

```text
【后端实现评审】<变更链接>
结论：PASS / FAIL
阻断项（FAIL 时必填，每项含 理由 / 涉及点 / 修改方向）：
- ...
建议项（非阻断）：
- ...
与上一轮修改清单核对（复审时）：已解决 X 项 / 未解决 Y 项
轮次：第 N / 3 轮
```

结论与修改清单**汇报给 Leader**，不自行改代码、不自行通知 BackendDev。

## 边界

- 只评后端契约与实现、单测，不评前端、UI、需求、架构设计本身、测试用例。
- 不替代 Leader 的通用门禁（`multica-verification` skill）。
- 架构层面分歧交 ArchReviewer，你只管实现层质量。
- 第 3 轮仍 FAIL → 标注「升级人类」，交 Leader 处理，停止循环。
